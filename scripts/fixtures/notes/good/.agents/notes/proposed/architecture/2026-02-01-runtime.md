# Agent Note: Split runtime into layers

Status: proposed

## Problem

The runtime does too many jobs in one place.

## Proposal

Introduce a layered runtime with one responsibility per layer.

## Alternatives considered

- Keep the monolith: less churn, but every change touches the core.
- Microservices: isolation, but too heavy for one operator.

## Acceptance criteria

Each layer builds and tests pass in isolation.

## Risks

The seam may leak; rollback keeps the old core until layers settle.

## Revisit signal

Revisit if the seam leaks more than twice in a month.
