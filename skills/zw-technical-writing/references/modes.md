# Document modes

One document holds one mode. The detail below is what each mode asks of the writing, past the one-sentence summary in the skill body.

## The compass

Two questions pick the mode. Does the content inform action (doing) or understanding (thinking), and does it serve learning or work?

- Action plus learning is a tutorial.
- Action plus work is a how-to.
- Understanding plus work is reference.
- Understanding plus learning is explanation.

Ask the compass of a whole document, or of one sentence inside it.

## Tutorial

Learning by doing. The learner's success is your job, not theirs.

- Open by saying what the learner will build, not what they will learn.
- Every step produces a visible result, early and often, and the text says what that result looks like: the expected output, the prompt change, the log line.
- Cut explanation to one clause and a link.
- Stay concrete, and write as "we", in commands. "First do x. Now do y."

## How-to

Steps to a goal. Solve a problem a person has, not an operation a machine can perform.

- Assume competence and skip the teaching.
- Action only: no digression, no background, and no completeness for its own sake. Link the material that would have gone there.
- Allow forks and judgment. "If you want x, do y."
- Name the guide by the task, so "How to calibrate the radar array" replaces "Radar array calibration".

## Reference

Facts for lookup. Only describe, with no instruction, no persuasion, and no opinion.

- Be dry, complete, and sure. State facts, options, limits, and errors with no hedging.
- Mirror the structure of the thing described, so the code and the docs can be navigated side by side.
- Put material where readers expect it, and generate it from the code wherever the code can already say it.

## Explanation

Understanding and why. One bounded topic, readable away from the product.

- Each title should tolerate an implicit "About" in front of it.
- Anchor on a real why question, not on a topic label.
- Give the context: the design decisions, the history, the constraints, and the alternatives that lost.
- Opinion is allowed here and nowhere else.

## Never mix

A reference table inside a tutorial, hand-holding inside reference, and an argument inside a how-to are each a mode leaking into another. Split the material out and link it.
